# ReconcileHub v2 — Architecture Direction

## Goal

ReconcileHub is evolving from a single Streamlit reconciliation application into an internal platform that hosts multiple reconciliation modules owned by different colleagues.

The existing Streamlit application remains the stable reference implementation during migration. The target UI is a React/TypeScript SPA backed by a Python API and the existing reconciliation engines.

## Migration principles

1. Do not rewrite working reconciliation logic just to change the UI.
2. Extract business logic from Streamlit pages before replacing the UI.
3. Keep each reconciliation module independent behind a common contract.
4. Authorization must be enforced by the backend, not only hidden in the frontend.
5. Analytics should have a platform layer and module-specific layer.
6. Audit events must be generated by backend operations and support structured filtering.
7. New reconciliation modules should be added through Git and code review, not by executing arbitrary uploaded Python files.
8. Keep the Streamlit application operational until the React frontend covers the required workflows.

## Planned module contract

Each reconciliation module should eventually expose a predictable interface similar to:

```python
class ReconciliationModule:
    id: str
    name: str
    version: str

    def validate(self, inputs): ...
    def run(self, inputs, config): ...
    def get_results(self, run_id): ...
    def get_analytics(self, run_id): ...
    def export(self, run_id, format): ...
```

The exact API will be finalized after the current Bank RRN flow is decomposed into reusable services.

## Migration phases

### Phase 1 — Foundation
- clean repository hygiene
- preserve current Streamlit production path
- document target architecture
- identify business logic embedded in UI pages
- establish tests around the current reconciliation engine

### Phase 2 — Backend boundary
- introduce FastAPI application structure
- expose Bank RRN through API endpoints
- move authentication/authorization decisions to backend services
- add persistent reconciliation run metadata

### Phase 3 — React frontend
- migrate navigation/layout/dashboard
- migrate Bank RRN workflow
- migrate analytics and audit UI
- connect frontend to FastAPI

### Phase 4 — Platformization
- module registry
- module-level permissions
- module-specific analytics
- advanced audit log
- shared file handling
- background jobs for large reconciliation runs

### Phase 5 — Streamlit retirement
- verify functional parity
- run pilot users on React version
- retire Streamlit only after the corporate deployment path is proven
